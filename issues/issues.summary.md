
# 问题列表

本页是**索引**：每个问题一个二级段落（`##`），标题不超过 80 个字符，下面只放一行状态 + 详情链接。详细描述与修复方案拆到 `issues/issue-<编号>.md`，索引页保持紧凑。

> **已完成归档**：整条 issue 的全部功能完成后，索引段从这里移到 [`issues.done.md`](issues.done.md)（链接不变）；未完成的一律留本页。

> **下一个可用编号：`126`** —— `1`–`29` 是历史编号（源自已归档删档的旧问题清单，原文见 git 历史），新条目**一律从 `50` 起顺序分配**，不与历史编号冲突。

**格式约定**

**索引页（本文件）**

- `## <编号>. <标题>`，标题 ≤ 80 字符，保留真 `##` 以维持锚点 / TOC / 编辑器按标题折叠。
- 标题下**只放一行**：`- [x]` 或 `- [ ]` + 状态摘要 + `→ [详情](issue-<编号>.md)`。
- 全部子场景都完成才打 `[x]`；部分修复留 `[ ]`，摘要里写清比例与剩余项，不要用一个总勾掩盖未完成部分。
- 格式约定与 issue 列表之间用 `---` 分隔线断开，列表区从分隔线下方开始。

**详情页（`issue-<编号>.md`）**

- `# <编号>. <标题>` + 返回索引链接 + 完整状态 checkbox 清单（常显，不折叠）。
- 固定两个三级小节 `### 详细描述`、`### 修复方案`，前面加 `---` 分隔线（沿用旧待办清单的约定）。
- **逐块折叠**：`###` 标题保留做锚点；小节内每个带标签的块（现象 / 最小复现 / 根因 / 边界 / 影响 / 已实施 / 验证 / 未实施 / 已知限制 / 曾否决 / 绕过）各用一个 `<details>`，summary 用「图标 + 原标签名」。

**通用**

- ⚠️ checkbox 必须是列表项 `- [x]`。`## [x] 标题` **不会渲染成勾选框**：GFM 任务列表只认列表项，标题里的 `[x]` 会原样显示。
- ⚠️ `<summary>` 后**必须空一行**，否则块内 markdown 不解析（加粗/列表/表格退化成纯文本）；`</details>` 前同样要空一行。
- 编号沿用历史原编号，不重排（条目之间存在 `#22` / `#23` 这类交叉引用）。
- **编号分配**：`1`–`29` 是历史编号（乱序，含已修复的 22/24/29 空档）；从旧待办清单迁入的条目及今后新增条目**一律从 `50` 起顺序分配**（`50`、`51`、`52`……），不与历史编号冲突。**下一个可用编号见页首**。
