# Koala 语言设计规范：整数算术与类型系统 (v1.0 Final)

## 一、先看结论

| 维度 | Koala 最终方案 | Go | Rust | 合理性评级 |
| :--- | :--- | :--- | :--- | :--- |
| **算术：小类型运算** | 提升到 64 位计算，结果为大类型 | 不提升，原地 wrap | 不提升，debug panic / release wrap | ✅ 精度优先，消除静默溢出 |
| **算术：跨符号混合** | ❌ 编译错误 | ❌ 编译错误 | ⚠️ 允许（隐式转无符号，历史包袱） | ✅✅ 零成本消灭一大类 CVE |
| **算术：溢出处理** | 常量期必报错；运行时默认 wrap，`--int-trap` 下 panic | 永远静默 wrap | debug panic，release wrap；需手动 API | ✅ 分层最清晰，可控性最强 |
| **位运算：结果类型** | 提升计算后**掩码回原位宽**，保持小类型 | 保持小类型 | 保持小类型 | ✅ 位宽守恒，避免 C 的类型污染 |
| **窄化：隐式转换** | 默认禁止，仅 `wrap {}` 块内合法 | 允许（静默截断） | 禁止（必须 `as`） | ✅ 安全与表达力的最佳平衡 |
| **窄化：显式转换** | `wrap` 内无条件截断；外部受全局 Flag 控制 | 永远静默截断 | `as` 永远静默截断 | ✅ 沙盒语义绝对确定 |

**一句话总结**：Koala 在算术上选择“精度优先”（64 位提升），在位运算上选择“位宽守恒”（掩码回原位宽），在窄化上选择“局部沙盒确定性”（`wrap` 块）。三者组合消除了 Go/Rust/C 中最典型的数值 bug，代价是密集小整数场景需配合 `wrap` 块使用。

## 二、维度一：算术运算

### 2.1 核心规则
-   **同符号提升**：`uintN op uintM → uint64`，`intN op intM → int64`。操作数自动零扩展/符号扩展至 64 位。
-   **结果类型**：运算结果**始终为 64 位**，不自动降级回原始小类型。
-   **异号禁止**：混合 signed/unsigned（如 `int8 + uint8`）直接**编译错误**。
-   **溢出分层**：常量表达式溢出 = 编译硬错误；变量运行时默认 wrap，`--int-trap` 下 panic。
-   **字面量默认**：整数字面量默认 `int64`，浮点默认 `float64`。

### 2.2 与 Go / Rust 差异对比

| 关键点 | Go | Rust | Koala | 评价 |
| :--- | :--- | :--- | :--- | :--- |
| 小类型加法 | `uint8+uint8=uint8`，静默截断 | `u8+u8=u8`，debug panic | `uint8+uint8=uint64`，永不溢出 | Koala 胜。消除最常见静默错误源 |
| 跨符号比较 | 禁止 | **允许**（-1 < 2u32 = true） | 禁止 | **Koala 完胜**。Rust 官方承认的历史包袱 |
| 默认类型 | `int`（平台相关 32/64） | `i32` | `int64` | Koala 更贴合现代 64 位架构 |
| 溢出检查 | 完全没有 | 靠构建 profile，粒度粗 | 常量硬错 + `--int-trap` 标志 | Koala 语义明确，可控性强 |

### 2.3 合理性评估

**✅ 极其合理的设计**
1.  **中间计算不丢精度**符合人类数学直觉。`a + b` 不该比数学上的 `a+b` 小。
2.  **跨符号族禁止**单条规则消灭一大类 CVE，成本为零。
3.  **常量期硬错误不可关闭**——唯一能“零成本消除已知错误”的层次。

**⚠️ 需要警惕的代价**
1.  **模运算语义丢失**：`uint8(2) - uint8(3)` 结果是巨大的 `uint64` 而非 `255`。哈希/CRC/像素混合等依赖模运算的场景必须配合 `wrap {}` 块。
2.  **64 位边界仍需兜底**：提升只保护到 64 位。`uint64.max + 1` 仍需 `--int-trap` 捕获，规范中必须明确声明，防止用户形成“Koala 算术永不出错”的错误心智模型。

## 三、维度二：位运算

### 3.1 核心规则
-   **计算提升**：与算术一样，先提升到 64 位进行位操作。
-   **即时掩码（关键）**：计算完成后，结果**立即截断/掩码回操作数的原始位宽**。
-   **结果类型**：保持**原始小类型**（如 `~uint8(0)` = `uint8(255)`，而非 `uint64`）。
-   **异号禁止**：跨符号族位运算同样编译错误。
-   **移位计数**：强制 `uint` 类型，负值/超位宽由 `--int-trap` 控制行为。

### 3.2 与 Go / Rust 差异对比

| 关键点 | Go | Rust | Koala | 评价 |
| :--- | :--- | :--- | :--- | :--- |
| 结果类型 | 保持原位宽 | 保持原位宽 | 提升后掩码回原位宽 | 对外可观察结果一致，中间不丢高位信息 |
| 按位取反 | `^x` | `!x`（与逻辑非共用） | `~x` | Koala 语义清晰，无歧义 |
| C 语言陷阱 | `~uint8` 可能符号扩展 | 无此问题 | **彻底杜绝** | Koala 最优 |

### 3.3 合理性评估

**✅ 三个维度中设计最漂亮的**
1.  **“掩码回原位宽”宣告：位运算是位级操作，不是数值操作。** 既享受提升带来的中间一致性，又守住位宽边界。
2.  **与算术形成正交分工**：算术负责“值”（允许增长→大类型）；位运算负责“位”（位宽固定→回原位宽）。有明确物理依据。
3.  **统一原则表述**：> *算术运算的结果类型由“值的范围”决定；位运算的结果类型由“位的宽度”决定。*

## 四、维度三：窄化与 `wrap` 块

### 4.1 核心规则
-   **隐式窄化**：默认**编译错误**。唯一例外：`wrap { }` 块内部。
-   **显式窄化**：
    -   `wrap { }` 块内：**无条件截断**，无视全局 Flag。
    -   `wrap { }` 块外：受 `--int-trap` / `--int-wrap` 控制。
-   **`wrap` 块作用域**：**仅限函数体内部**。禁止模块顶层/全局/类型定义中使用。
-   **语义主权**：`wrap` 块内所有窄化行为绝对确定，不可被局部覆盖，无 `strict` 反向机制。

### 4.2 合理性评估

**✅ 解决了“显式转换地狱”与“语义割裂”**
1.  **正交性**：普通代码 = 安全优先 + 全局策略；`wrap` 块 = 性能/底层优先 + 局部绝对确定性。
2.  **可审计性**：看到 `wrap` 就知道“全截断”，看到普通代码的显式转换就知道“受 Flag 保护”。无灰色地带。
3.  **编译器友好**：一个布尔标记 `InWrapBlock` 搞定一切，无状态机、无优先级仲裁。

**⚠️ 设计约束**
-   倒逼函数职责单一：若既有截断又有严格检查需求，应拆分函数。`wrap` 块是明确的代码审查信号。

## 五、交叉验证：一个用例看穿三家

```koala
let a: uint8 = 200
let b: uint8 = 100
```

| 表达式 | Go | Rust (debug) | Koala | 评价 |
| :--- | :--- | :--- | :--- | :--- |
| `a + b` | `44` (uint8, 静默错) | panic | `300` (uint64) ✅ | Koala 最安全 |
| `b - a` | `56` (mod 256) | panic | `18446744073709551516` (uint64) ⚠️ | Koala 把错误变成显眼的大值 |
| `a & b` | `32` (uint8) | `32` (u8) | `32` (uint8) ✅ | 三家一致 |
| `a == int8(100)` | ❌ | ❌ | ❌ | Koala 跨符号禁止 |
| `wrap { a + b }` | N/A | N/A | `44` (uint8, 确定截断) ✅ | Koala 独有沙盒 |

## 六、最终评分与落地建议

### 6.1 综合评分

| 维度 | 评分 | 理由 |
| :--- | :--- | :--- |
| **算术运算** | **8.5/10** | 提升策略 + 跨符号禁止 + 分层溢出检查，整体优于 Go/Rust；扣分项是模运算场景需 `wrap` 配合 |
| **位运算** | **9.5/10** | 提升计算 + 掩码回位宽，既避免 C 的类型污染，又守住位宽边界，三家最优 |
| **窄化与 wrap** | **9.5/10** | 沙盒语义绝对确定，解决显式转换地狱，编译器实现极简 |
| **整体一致性** | **9/10** | “值 vs 位”正交分工清晰，有统一原则可解释 |

### 6.2 三条落地建议（已纳入规范）

1.  **`wrap` 块作为模运算的唯一入口**：不为算术引入 `+%` 等语法糖。`wrap { }` 本身就是语法糖，且语义更丰富（同时解禁隐式窄化）。密码学/哈希/像素混合等场景统一使用 `wrap` 块，保持语言表面积极简。
2.  **明确移位语义**：移位计数强制 `uint` 类型；超位宽/负值行为由 `--int-trap` 控制（trap 下 panic，wrap 下掩码计数）。
3.  **规范中写明 64 位边界**：在文档显著位置声明“提升只保护到 64 位”，并给出 `uint64` 溢出示例与 `--int-trap` 的必要性说明。

### 6.3 编译器实现检查清单

| 阶段 | 检查项 | 预期行为 |
| :--- | :--- | :--- |
| **解析器** | 模块顶层 `wrap {}` | ❌ 报错：`wrap block is only allowed inside function bodies` |
| **类型检查** | 普通代码隐式窄化 | ❌ 报错：`implicit narrowing requires wrap block` |
| **类型检查** | 跨符号算术/比较/位运算 | ❌ 报错：`cannot mix signed and unsigned types` |
| **IR 生成** | 算术运算 (<64位) | ✅ 插入 `ZEXT`/`SEXT` → 64位运算指令 |
| **IR 生成** | 位运算 (<64位) | ✅ 插入 `ZEXT` → 64位运算 → `AND mask` → 结果回小类型 |
| **IR 生成** | `wrap` 块内任意窄化 | ✅ 生成 `TRUNC`，不查询全局 Flag |
| **IR 生成** | `wrap` 块外显式窄化 | ✅ 根据全局 Flag 生成 `TRUNC` 或 `CHECK_TRUNC` |

### Koala 统一提升规则

**算术、比较、位运算三类二元运算符使用同一套提升规则：**

| 操作数组合 | 提升结果 | 说明 |
|---|---|---|
| `uintN` + `uintM` | `uint64` | 两个都是无符号，提升为 `uint64` |
| `intN` + `intM` | `int64` | 两个都是有符号，提升为 `int64` |
| `intN` + `uintM` | `int64` | 混合符号，提升为 `int64` |
| `uintN` + `intM` | `int64` | 混合符号，提升为 `int64` |

其中 `intN` / `uintN` 包括 `int8/16/32/64`、`uint8/16/32/64`。

字面量固定为 `int64`，所以：

```koala
x + 1          // 1 是 int64，按混合符号规则提升到 int64
u64 + 1        // uint64 + int64 → int64
u64 + u64(1)   // uint64 + uint64 → uint64
```

溢出语义仍然是：**int64 / uint64 默认 wrap，不 trap。**

### 这个设计比 C/C++ 好在哪

C/C++ 最麻烦的地方是：

- 小整数先提升到 `int` / `unsigned int`；
- 有符号和无符号混合时，可能静默转成无符号；
- `-1 < (unsigned int)1` 会变成 `4294967295 < 1`；
- 位运算、比较、算术的提升路径还容易让人混淆。

Koala 现在这套规则把三类运算符统一了：

- 不再区分“算术提升”和“比较提升”；
- 不再区分“位运算提升”和“算术提升”；
- 只要两个都是无符号，就进 `uint64`；
- 只要出现有符号，就进 `int64`。

这样用户只需要记一条：**全无符号 → uint64；否则 → int64。**

### 唯一要注意的点

`uint64 + int64` 结果是 `int64`，不是 `uint64`。这意味着：

```koala
let a: uint64 = 0xFFFFFFFFFFFFFFFF
let b: int64 = -1
let c = a + b   // 结果是 int64
```

这里 `a` 从 `uint64` 提升到 `int64` 时会按二进制补码解释，`0xFFFFFFFFFFFFFFFF` 变成 `-1`，所以 `-1 + -1 = -2`。

如果这是你想要的语义，那规则就完整了；如果你希望 `uint64 + int64` 仍然报错、强制显式 cast，那就得把这条从“混合符号 → int64”里单独摘出来。

明白了，规则彻底钉死：

### Koala 整数提升规则（最终版）

**适用范围：** 算术、比较、位运算三类二元运算符统一使用同一套规则。

**提升逻辑：**

| 操作数组合 | 行为 |
|---|---|
| 两个操作数都是 1/2/4 字节的无符号（`uint8/16/32`） | 提升到 `uint64` |
| 其他 1/2/4 字节组合（含任一有符号） | 提升到 `int64` |
| `int64 op uint64` 或 `uint64 op int64` | **报错**，必须显式 cast |
| 同号 64 位（`int64 op int64` / `uint64 op uint64`） | 保持原类型 |

**字面量：** 统一为 `int64`。

**溢出：** `int64` / `uint64` 默认 wrap，不 trap。

**窄化：** 赋值/返回不允许隐式窄化。

### 关键点

`int64 op uint64` 报错这条把 C++ 最危险的坑彻底堵死了——C++ 里 `int64` 会被静默转成 `uint64`，负数瞬间变成巨大正数，Koala 这里直接卡住，用户必须显式写 `int64(x)` 或 `uint64(y)`。

而 1/2/4 字节场景下，跨符号提升为 `int64` 是安全的（值域完全容纳得下），所以可以放行，不用到处写 cast。

### 日常写法示例

```koala
let a: int8 = 1
let b: uint32 = 2
let c = a + b          // int64，OK

let x: int64 = 1
let y: uint64 = 2
let z = x + y          // ❌ 报错，需显式 cast
let z = int64(y) + x   // ✅ OK
```
